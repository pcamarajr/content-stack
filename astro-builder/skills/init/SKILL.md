Interactive setup wizard for astro-builder. Configures the plugin for your Astro project through a guided conversation.

**Arguments:** $ARGUMENTS

---

## Step 0 — Route

Parse $ARGUMENTS:

- **`project`** → Read `skills/init/rounds/project.md` (relative to plugin root) and follow its instructions completely
- **`lighthouse`** → Read `skills/init/rounds/lighthouse.md` (relative to plugin root) and follow its instructions completely
- **Empty** → Run the Status Dashboard (below)
- **Unknown argument** → Tell the user the valid options: `project`, `lighthouse`

After completing any round, always end with a short "What's next?" line pointing to the next incomplete round.

---

## Status Dashboard

Only runs when $ARGUMENTS is empty.

### 1. Detect project basics

Try to read `package.json` → extract `name`, plus the `astro` version from `dependencies` /
`devDependencies` (resolve it with `pnpm list astro` if the range is not a plain version).
Run `node -v` → record the local Node version.
Try to read `CLAUDE.md` → check if it was generated by astro-builder (look for `.astro-builder/` references).

### 2. Determine round completion

| Round | Complete when |
|-------|---------------|
| project | `CLAUDE.md` exists AND all five guidance files exist: `.astro-builder/style-guide.md`, `.astro-builder/content-schema.md`, `.astro-builder/design-system.md`, `.astro-builder/anti-patterns.md`, `src/styles/global.css` — AND the code scaffold exists: `astro.config.ts`, `tsconfig.json`, `src/content.config.ts`, `src/layouts/BaseLayout.astro`, all four of `src/lib/i18n.ts` / `src/lib/urls.ts` / `src/lib/format.ts` / `src/lib/content.ts`, at least one `src/i18n/*.json`, `public/robots.txt` |
| lighthouse | `.astro-builder/lighthouse.json` exists AND `.astro-builder/pre-push.sh` exists AND `.husky/pre-push` exists |

Use 🔄 (started) when some but not all required files for a round exist.

### 3. Output

```text
## astro-builder — Setup Status

Site:   [name from package.json, or "—"]
Astro:  [detected astro version, e.g. 7.1.3, or "—"]
Config: .astro-builder/ ([found | not found])

✅ /astro-builder:init project    — [one-line summary, e.g. "CLAUDE.md + config files + site scaffold generated"]
⬜ /astro-builder:init lighthouse — not started

→ Next: /astro-builder:init [first incomplete round]

What each step does:
  project    — Scan repo, interview, generate CLAUDE.md + .astro-builder/ config files, scaffold the site code (config, layout, lib, i18n, SEO surface)
  lighthouse — Set up automated Lighthouse CI auditing on git push
```

When the detected Astro major is below 7, or the local Node is below 22.12.0 (Astro 7's
`engines.node`), print one warning line directly under the dashboard — for example:

```text
⚠️  Astro 6.4.1 detected (astro-builder targets Astro 7) — upgrade guide: https://docs.astro.build/en/guides/upgrade-to/v7/
⚠️  Node 20.11.0 detected — Astro 7 requires Node >= 22.12.0: https://docs.astro.build/en/guides/upgrade-to/v7/
```
